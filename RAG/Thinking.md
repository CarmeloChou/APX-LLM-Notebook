## 数据解析

### DAG任务图

任务有向无环图清晰定义了复杂工作流，一个典型的 RAG 数据处理流程就可以被构建成一个 DAG：
`读取文件 -> 解析文本 -> 文本分块 -> 生成嵌入 -> 存入向量数据库`

必须先读取文件才能解析文件。但是读取文件是可以并行的。

### 独立扩展

- **解析 (Parsing) 和分块 (Chunking)**：主要是字符串操作和逻辑判断，属于 **CPU 密集型** 任务。
- **生成嵌入 (Embedding)**：需要运行大型神经网络模型进行计算，属于 **GPU 密集型** 任务。

在传统的单机脚本中，CPU 和 GPU 的计算是串行的，可能导致 GPU 在等待 CPU 处理数据时空闲，或者 CPU 处理完数据后等待 GPU。而使用 Ray Data 的 DAG，你可以将这两种任务解耦：

1. **资源隔离**：你可以在 Ray 集群中指定，解析任务只在纯 CPU 节点上运行，而嵌入任务则调度到带有 GPU 的节点上运行。
2. **独立扩缩容：**当你发现文件解析太慢，成为瓶颈时，你可以**只增加 CPU 节点的数量**，而无需为昂贵的 GPU 资源付费。当你需要处理海量数据，嵌入计算跟不上时，你可以**只增加 GPU 节点的数量**，让嵌入任务并行处理，而 CPU 资源保持不变。

## 云架构

由于k8s包括master节点和worker节点。任务节点数量取决于任务编排，而服务器租赁的费用与数据传输有关系。如果使用公网ip，相当于流量从机房流入机房（可能是自己，也可能是别的机房），这种传输方式不稳定且价格昂贵，一般而言，同一机房使用局域网ip即可，云服务器厂商内部传输，免费且速度快。非要涉及到混合云，即主节点可能为阿里云，worker节点可能为autodl算力平台，如果单纯使用公网ip通信，价格非常昂贵，以下为主要方式对比：

| 方案                 | 通信路径                  | 流量费用              | 适用场景                 | 核心优势                          |
| :------------------- | :------------------------ | :-------------------- | :----------------------- | :-------------------------------- |
| **公网流式传输**     | Head -> 公网 -> Worker    | **极高** (双向收费)   | 极小文件，实时性要求极高 | 数据强一致性，无需存储            |
| **对象存储内网下载** | OSS -> **内网** -> Worker | **0元** (同地域内)    | **同云厂商**集群         | 速度最快，无需管理存储，存算分离  |
| **数据同步/本地化**  | 提前同步 -> **本地磁盘**  | **低** (仅同步时产生) | **跨云/混合云**集群      | 计算时**0延迟**，彻底摆脱网络依赖 |
